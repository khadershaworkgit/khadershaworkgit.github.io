What is C-T-C-O? (The Foundational Prompting Framework)

C-T-C-O is the industry-standard 4-part software engineering formula for writing prompts that prevent AI hallucinations, mathematical errors, and sloppy code:

1. C = CONTEXT

The system environment, language version, and architecture (e.g., Python 3.11 checkout engine receiving CartItem dataclasses).

2. T = TASK

The single, unambiguous programming objective (e.g., Write calculate_order_totals() with volume and tier discounts).

3. C = CONSTRAINTS

Non-negotiable engineering rules and boundaries (e.g., Use Decimal with ROUND_HALF_UP, no binary floats, O(N) complexity).

4. O = OUTPUT

The exact schema required (e.g., Pure typed Python code with dataclass models, docstrings, and 3 pytest test cases).

ℹ️ R-T-C-F-C Connection: R-T-C-F-C below is the expanded 5-part version of C-T-C-O where Role is explicitly separated from Context, and Format is separated from Output!

Task: Write a Prime Number Checker

Basic prompts produce slow $O(N)$ brute-force loops that crash on edge cases. The engineered prompt specifies mathematical efficiency and negative handling.

❌ Basic Prompt: "write prime check" O(N) Brute Force & Missing Guards 
def is_prime(n):
    # Bug 1: Fails on 0, 1, and negative numbers!
    for i in range(2, n): # Inefficient O(N) loop
        if n % i == 0:
            return False
    return True # Bug 2: Returns True for n <= 1
✅ Engineered Prompt: C-T-C-O Specified O(√N) Time Complexity & Boundary Proof 
import math

def is_prime(n: int) -> bool:
    """Checks primality with O(sqrt(N)) time complexity and boundary validation."""
    if n <= 1:
        return False
    if n <= 3:
        return True
    if n % 2 == 0 or n % 3 == 0:
        return False
    # Check 6k +/- 1 optimization up to sqrt(n)
    for i in range(5, math.isqrt(n) + 1, 6):
        if n % i == 0 or n % (i + 2) == 0:
            return False
    return True

    if not urls: return []
    # FIX: Semaphore throttles concurrency to safe OS limit
    sem = asyncio.Semaphore(max_concurrency)
    conn = aiohttp.TCPConnector(limit=max_concurrency)

Prompt Engineering Cheat Sheet

6 ready-to-use production prompt templates. Click the copy button to copy any template to your clipboard.

1. Logic Synthesis
[ROLE]: Senior [Language] Architect. [TASK]: Implement [Functionality]. [CONSTRAINTS]: O([Complexity]) time, handle edge cases [X, Y, Z], zero external dependencies. [OUTPUT]: Fully typed code with docstrings.
2. Error Debugging & RCA
[CONTEXT]: [Runtime/Env]. [ERROR]: [Paste exact Traceback]. [CODE]: [Paste snippet]. [TASK]: 1) Root cause analysis. 2) Provide a targeted patch. 3) Write a unit test verifying the bug fix.
3. Structural Refactoring
[TASK]: Refactor this function to the Strategy Pattern. [DIRECTIVES]: Decouple [A] from [B] using Dependency Injection. Keep cyclomatic complexity under 3. Do not break external interfaces.
4. Code Audit & Explanation
[ROLE]: Security & Systems Auditor. [TASK]: Explain how this code works step-by-step. [AUDIT]: Highlight any potential memory leaks, race conditions, or unhandled exceptions under high concurrency.
5. Automated Test Generation
[TASK]: Write a parameterized [pytest/jest] test suite for [Class/Function]. [COVERAGE]: Happy path, null inputs, boundary values, and mock network failures using in-memory mocks.
6. Performance Optimization
[TASK]: Optimize this algorithm for [Latency / Memory]. [CONSTRAINTS]: Reduce time complexity from O(N^2) to O(N log N) or O(N). Avoid redundant allocations. Provide before/after benchmarks.
